# infra/attachment 的设计

本页写这个组件为什么这样设计：术语、拥有的数据、状态、规则、命令与事件、依赖、实现状态与未决问题。写给要修改它的人与 AI。怎样使用、部署与配置在 `BRICKKIT.md`；代码在哪、怎样构建与测试在 `AGENTS.md`。

跨组件的规则在装配项目：附件与对象存储在协议 12（状态表、访问凭证、上传、扫描、下载、解除引用与保全、对账、参数、独立预期 FA01–FA35），保留类别在协议 11，后台工作在协议 01，审计在协议 03，附件类别的编码在安全 09a，注册表在协议 19；决定 D53（经 SDK 的存储端口）、D68（不调用业务组件）。对象的读写经线协议第 19 章的存储端口。首批范围是装配项目阶段计划 C9 的 P0 定的，P1 的考设计改过一轮（AI 定，待复核）。

## 边界

附件：替父记录的属主保存附件的记录与对象，按属主经系统面申请的短期凭证让用户上传、下载；保证下载的内容就是确认时检查（与扫描）过的那份。

| 不在这里 | 归谁 |
| --- | --- |
| 用户能不能给这张单据加附件、能不能看某类附件（按类别对应字段的读写资格与业务条件） | 父记录的属主；本组件只核对申请凭证的是父资源类型的属主 |
| 附件类别的声明 | 属主在自己的资源定义里（`attachment_categories`），经授权组件的定义目录到本组件 |
| 父记录作废、关闭、销毁、擦除、保全的业务判断与保留起算日期 | 属主，经系统面命令本组件 |
| 导出文件、事件的大载荷、冷数据、运行档案 | 各自的属主组件（协议 12 的对象属主表） |

## 术语

| 业务叫法 | 定义 | 代码标识符 |
| --- | --- | --- |
| 父记录 | 附件归属的记录：属主组件、资源类型、记录身份 | `parent` |
| 类别 | 属主为资源类型声明的附件种类：对应的字段、大小上限、允许的类型、敏感级别（普通、严格）、保留类别、版本；类别名按约定以属主组件的领域开头（例 `erp.purchase.order_contract`），在一个资源类型之内唯一；本组件不核对前缀（属主核对按资源类型做，名字不承担安全） | `category` |
| 类别快照 | 附件创建时类别的敏感级别、上限、允许的类型与保留类别：类别以后修改只对新附件生效 | — |
| 上传会话 | 一次上传：暂存键、预签名上传地址、确认凭证、时限 | `upload` |
| 内容版本 | 附件的一份内容；替换内容是新的版本，经确认与扫描后成为当前版本 | `version` |
| 暂存键、最终键 | 客户端上传到暂存键 `staging/<会话>`；确认时复制到不可覆盖的最终键 `objects/<附件>/<版本>`，扫描与下载只针对最终键 | — |
| 访问凭证 | 随机的不透明值，只存摘要；绑定用户、附件（或上传会话）、操作、内容版本与到期 | `credential` |
| 解除引用、恢复、清除 | 属主让附件离开父记录（宽限期内可恢复）；宽限期与保留都过后清除（删对象）；擦除命令立即清除 | `detached`、`purged` |
| 保全 | 属主下达的“不得清除”，范围是一个附件或一个父记录的全部附件 | `hold` |

## 拥有的数据

| 表 | 内容 | 终态与保留 |
| --- | --- | --- |
| `category` | 授权组件目录的副本：资源类型、属主组件、类别名、类别的全部属性与版本、目录修订（整份替换：附件自己存快照） | 随目录 |
| `attachment` | 身份、父记录、类别名与版本、类别快照、状态、解除引用前的状态、当前版本、待定版本、文件名、上传者、解除引用的时刻、保留起算日期、清除的时刻 | `purged` 的行与版本行保留（键、摘要、时刻；对象已删） |
| `version` | 附件、版本号、暂存键、最终键、大小、检测到的类型、SHA-256、扫描结果（引擎、签名版本、结果、被扫描内容的摘要；未扫描）、状态（`uploading`、`finalizing`、`pending_scan`、`clean`、`rejected`、`quarantined`、`superseded`）、会话到期、进入 `finalizing` 的时刻 | 随附件；`rejected`、`quarantined` 的对象 30 天后删 |
| `credential` | 摘要、操作（`confirm`、`download`）、绑定的用户、附件、版本、到期、用过的时刻 | 到期后 1 天删 |
| `hold` | 身份、范围（附件或父记录）、原因、下达与解除的时刻 | 解除后保留 |

## 状态

| 当前状态 | 事件 | 守卫 | 结果 |
| --- | --- | --- | --- |
| （无） | 属主申请上传会话 | AT02 | `uploading` |
| `uploading` | 用户确认 | 确认凭证有效（AT04）；暂存对象已存在（不在时答可重试的“上传未完成”，不消耗凭证） | `finalizing` |
| `finalizing` | 复制并检查完成 | 最终对象的大小与检测到的类型符合类别快照 | 开启扫描：`pending_scan`；关闭扫描：`available`（未扫描） |
| `finalizing` | 检查失败 | — | `rejected` |
| `finalizing` | 10 分钟未完成（崩溃在复制前后） | 认领到这个版本（条件更新） | 重做：最终键已在时直接检查它，不在时重新复制；暂存也没有时 `rejected` |
| `pending_scan` | 扫描干净 | 最终对象的摘要等于记录的 | `available` |
| `pending_scan` | 发现威胁或摘要不符 | — | `quarantined` |
| `pending_scan` | 扫描出错 | — | 不变，重试；超过 1 小时告警 |
| `uploading` | 会话到期未确认 | — | `rejected`（未确认） |
| `available` | 替换内容 | 属主为这个附件申请了上传会话 | 不变：新版本作为待定版本走确认与扫描；干净时当前版本切到它，旧版本 `superseded`（对象按附件的保留留着）；待定版本被拒或隔离时当前版本不变 |
| `available` | 下载或对账发现最终对象缺失 | — | `missing`（告警；不报告为“不存在”） |
| `missing` | 对账发现对象回来了且摘要相符 | — | `available` |
| 除 `purged` 外的任何状态 | 属主命令解除引用 | — | `detached`（记下原状态）；进行中的上传会话与待定版本作废（`rejected`），它们的凭证失效 |
| `detached` | 属主命令恢复 | 在宽限期内 | 记下的原状态；原状态是 `uploading`、`finalizing`、`pending_scan` 的（解除引用时作废了）恢复成 `rejected`，属主重新申请上传 |
| `detached` | 清除 | 宽限期已过、保留起算日期已设、最短保留已到、没有生效的保全（同一个事务里检查） | `purged`，全部版本的对象删掉 |
| 除 `purged` 外的任何状态 | 属主命令按擦除清除（父记录被销毁或擦除） | 没有生效的保全 | `purged`，全部版本的对象删掉；保全中不变并告警 |
| `rejected` | 清理 | 会话已到期 | `purged`（新附件被拒：对象随即删除；替换中被拒的版本不在这一行，见 AT12） |

## 规则

| 规则 | 内容 |
| --- | --- |
| AT01 | **类别目录**：每分钟（与启动时）按修订向授权组件读附件类别目录，整份替换本地副本；读不到时用已有的副本，超过 15 分钟没更新告警。新业务组件上线只增加目录内容，本组件不改动、不重新发布（FA26） |
| AT02 | **属主核对**：系统面的每个命令，父资源类型在目录里时，调用者的服务身份必须是它的属主、类别必须属于它，否则 `PERMISSION_DENIED` 并写一条安全审计（FA24）；父资源类型还不在本地目录里（新组件刚上线、目录未同步），答可重试的 `DEFINITION_PENDING`，不写安全审计。附件必须属于命令给出的父记录 |
| AT03 | **上传会话**：属主给出父记录、类别、文件名、声明的大小与类型、替换的附件（可选）与用户；声明的大小超过类别上限、类型不在允许的类型里直接拒绝；本组件建 `uploading` 的附件（新附件时存类别快照）或待定版本、暂存键、预签名上传地址（签入长度与类型，15 分钟）与确认凭证（同时限） |
| AT04 | **确认**：用户凭确认凭证与自己的令牌请求。先查暂存对象的元数据：不在答可重试的“上传未完成”（不消耗凭证）。再在一个事务里原子地作废凭证（条件更新：存在、未用、未过期、绑定调用者、操作是确认、会话相符；否则 404，与不存在一样，FA22、FA23、FA25）并转 `finalizing`、预留最终键；**然后**在事务外把暂存对象条件复制到最终键（线协议 P19.4），**再**读最终对象自己算摘要与大小、按内容检测类型（不信客户端声明与元数据，FA03）、按类别快照检查；最后在事务里记下并转 `pending_scan` 或 `available`。确认期间客户端覆盖暂存对象改变不了最终对象（FA02、FA21） |
| AT05 | **扫描**：部署配置 `ATTACHMENT_SCAN` 选扫描端口：`off`（开发与格的默认：直接 `available`，标“未扫描”，FA05）或 `clamav`（以后）；扫描工作先读最终对象核对摘要，不符 `quarantined` 并告警；出错不算干净，重试，超过 1 小时告警（FA04）。从关闭改为开启时，已有的“未扫描”附件仍可用、仍标未扫描，扫描工作按批补扫 |
| AT06 | **下载**：只有 `available` 的附件（当前版本）能下载。普通类别：给属主一个预签名下载地址（5 分钟，强制作为附件保存，文件名在下载头里）。严格类别：给一个一次性下载凭证（1 分钟，原子作废，用一次），用户凭它与自己的令牌向本组件请求，本组件读最终对象转发字节，响应头固定 `Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: sandbox`，内容类型取检测到的类型（不是图片与 PDF 的一律 `application/octet-stream`），所以上传的 HTML 与 SVG 在应用的域名下不会执行（FA09）。签发前查最终对象的元数据，不在转 `missing` 并答“依赖不可用”（FA13） |
| AT07 | **列出**：属主按父记录列出附件（状态、类别、文件名、大小、类型、当前版本、是否未扫描），属主按用户的字段资格过滤类别（FA28） |
| AT08 | **解除引用与恢复**：属主命令；一个父记录的全部附件可以一次解除（单据作废，FA10）；宽限期 30 天内可恢复。解除引用之后，已签出的普通下载地址仍能用到它的有效期（5 分钟），这是声明的窗口 |
| AT09 | **保留与清除**：属主命令设置保留起算日期（可在解除引用时一起给，例：单据作废或关闭的日期）。保留类别的最短与最长保留由部署配置 `ATTACHMENT_RETENTION`（保留类别 → 最短天数、最长天数）给出，没给的是“待确认”（协议 11：待确认的从不销毁）。清除工作（每小时）在一个事务里检查宽限期已过、起算日期已设、最短保留已到（这三条与“类别的年限已给”写在查询里，永远清除不了的不占候选）、没有生效的保全（锁住附件行检查，与保全命令互斥），才转 `purged`，事务提交后删全部版本的对象。起算日期只往后移（属主的结束命令可能乱序到达，保留只会更长），移动是状态事件的一次改变。每天的对账告警：起算待定超过一年的已解除附件；最长保留已过而附件仍挂在父记录上的（销毁由属主按自己的数据销毁下令，AT10） |
| AT10 | **按擦除清除**：属主命令清除一个附件或一个父记录的某些类别（父记录被销毁或擦除），不等宽限期与最短保留；保全中的不清除并告警（FA20、FA34） |
| AT11 | **保全**：属主命令设置或解除，范围是一个附件或一个父记录的全部附件；设置时锁住它覆盖的附件行，清除的事务里检查（FA11）；已清除的附件不能保全（答 404） |
| AT12 | **清理与对账**：确认写下结果后删除暂存对象（只是暂存；删不掉的由每天的对账补）。每分钟：`finalizing` 超时的重做（AT04 的复制与检查，认领用条件更新）；会话到期的 `uploading` 转 `rejected` 并删暂存对象。每天：没有记录指向的最终对象、版本已不在上传或确认中的暂存对象（都超过 7 天）删除；`available` 而对象缺失的转 `missing`，`missing` 而对象回来的转回；`purged` 而对象仍在的继续删；替换中被拒或隔离的版本 30 天后删对象（FA12–FA14） |
| AT13 | **事件**：附件的状态、当前版本或保留起算每次改变（版本号加一），在本组件的流上发完整状态事件 `infra.attachment.changed.v1`（附件身份、父记录、类别、状态、当前版本、大小、类型、是否未扫描、版本号）；属主需要时订阅（显示附件数） |
| AT14 | **审计**：凭证的签发（上传会话与下载）与使用、严格类别的下载、解除引用、清除写审计（协议 03）；属主核对失败写安全审计 |

## 部署与替换

大文件的流量直达对象存储（预签名），只有严格类别经本组件转发；放外壳（`be/go-infra`）或单跑。部署要为对象存储提供浏览器可达的主机名，并给桶设跨源规则（浏览器直传）与暂存前缀的过期规则（协议 12）。同契约的实现可替换。

## 验证故事

1. 确认后再用仍有效的预签名地址上传，最终对象与扫描结果不变。
2. 把附件甲的下载凭证用于附件乙、别人用我的确认凭证、凭证过期、被篡改、用第二次：都被拒。
3. 组件甲为组件乙的资源类型申请凭证：被拒并留下安全审计。
4. 新业务组件声明自己的附件类别：本组件不改动、不重新发布。
5. 单据作废：属主解除引用并给出起算日期，宽限期与最短保留都过、没有保全时清除；保留年限没配的从不清除。
6. 严格类别的 HTML 文件经本组件下载，浏览器只保存、不执行。

- 扫描引擎的选择（ClamAV 等）与签名更新后是否回溯重扫：随客户要求。
- 分段上传（大于存储单次 `PUT` 的文件）：线协议第 19 章的“不在本版”；首批类别的上限都不超过 16 MiB（协议 12 的分段阈值）。
- 属主经系统面读内容自己转发（水印、脱敏，FA09 的另一种方式）、某类别在某父记录集合上的保全（FA32 的范围）：首批不做，属主要用时加命令。
- 清除意图写进证据存储（协议 12 的备份与恢复、协议 15）：首批只写审计，随整套恢复演练（C14）补。
- 各保留类别的年限是法规与客户合同的事：由部署配置给出，没给的待确认、从不清除。
